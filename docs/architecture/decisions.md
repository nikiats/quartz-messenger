# Архитектурные решения

## Протоколы взаимодействия

**Р1. Клиент <-> шлюз**: `WebSocket`, в силу необходимости дуплексного обмена сообщениями в реальном времени.

**Р2. Клиент -> сервис мессенджера**: `HTTP`, в силу широкой поддержки, включая веб-браузеры и приложения для мобильных устройств.

**Р3. Шлюз -> сервис мессенджера**: `HTTP`, в силу простоты реализации и отладки.

**Р4. Сервис мессенджера -> шлюз**: `HTTP`, причины аналогичны описанным для **Р3**.
