# Операции над данными

В соответствии с архитектурой необходимо разработать операции над хранимыми данными, которые позволят сохранить согласованность хранимых данных.

### 1. Проверка прав пользователя отправить сообщение

Входные данные:
- ID отправителя (senderId);
- ID чата (chatId).

Результат:
- право отправки (canSend).

**Алгоритм:**

1. Выполнить выбор в Cassandra `chat_members` по `(chatId, senderId)`;
2. Если запись не найдена или чат удален (`deleted` = `true`), `canSend` ложно;
2. Иначе, `canSend` истинно.

### 2. Отправка сообщения

Входные данные:
- контент (content);
- ID отправителя (senderId);
- ID чата (chatId);
- ID сообщения клиентский (clientMessageId).

Результат:
- ID сообщения Snowflake (messageId);
- время отправки (sentAt).

**Алгоритм:**

1. [Проверка возможности пользователя писать в чат](#1-проверка-прав-пользователя-отправить-сообщение). При отсутствии возможности - завершение.
2. Формирование ключа идемпотентности  `msgKey` = `"msg:{chatId}:{senderId}:{clientMessageId}"`
3. Сформировать Snowflake ID сообщения `messageId`;
4. Выполнить в Redis попытку установки `msgKey`: `messageId` (инструкция NX);
5. Неудача => заменить `messageId` на значение из Redis;
6. Успех => прочитать сообщение из Cassandra по полученному из Redis `messageId`;
7. Получить текущее время `sentAt`;
8. При удаче или неудаче, но в которой отсутствовало сообщение в Cassandra, выполнить вставку сообщения в Cassandra.
9. При вставке, вернуть новый `messageId` и `sentAt`, без вставки вернуть эти поля полученного сообщения.
